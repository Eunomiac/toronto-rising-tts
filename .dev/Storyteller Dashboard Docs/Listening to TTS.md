## Agent Routing

## 1. The model in one paragraph

All game state lives in TTS (`gameState`). TTS pushes small one-way messages whenever something the dashboard cares about changes; the dashboard server relays them to every open tab over Server-Sent Events and keeps the latest one per topic (per seat for `pcSeat`). **The dashboard never polls TTS.** A view gets its data from (1) the pushes, (2) the server's replay of cached pushes when it connects, and (3) at most one execute-lua fetch when it opens or after a game load. Every push carries a whole seat or a whole slice, so a view simply replaces what it had — there are no deltas to apply and no ordering to track.

## 2. What TTS broadcasts

Every event reaching a tab has the shape `{ topic, color?, data?, at }`, where `at` is the server receive time in epoch milliseconds.

| Topic | `data` | Sent when | How often |
| --- | --- | --- | --- |
| `pcSeat` (with `color`) | Slim seat snapshot: identity, Desire/Ambition, attributes, skills, specialties, trackers, Hunger, Blood Potency and derived values, badges, conditions, connection flags, plus sheet-extension fields (disciplines, advantages, XP, relationships). Same shape as one seat of `GlobalDashboardPcSheetSnapshot`, minus `playerData` | End of every `Sync.player(color)` (any per-seat change), and once at the end of a CSHEET Desire edit | Once per changed seat; unchanged seats are skipped |
| `projects` | none | Any project mutation; present-day clock change | Per mutation. Refetch with `GlobalDashboardProjectsSnapshot` if the view is showing projects |
| `reload` | none | TTS starts loading a game (server-generated) | Per load. Drop everything and refetch once |
| `notice` | `{ text }` | TTS refused or failed something the Storyteller started: scene Play refused before the blindfold (`refuseSceneApply` in `core/storyteller_scenes_panel.ttslua`), any table or scene change blocked by dice on the table (`RSL.alertAndBlockIfDiceOnTable`), a blindfold transition whose work failed (`reportTransitionFailure` in `core/hud_blindfold.ttslua`) | Per refusal. The Scenes tab shows it as a red notice with OK until dismissed; a replayed notice older than a minute is ignored |
| `phase` | `phase`, `subPhase`, `sessionNum`, `sessionName`, `sessionStartDowntime`, `memoriamActive` | Phase or subphase change, Memoriam enter/leave, full UI refresh (session number and name ride along) | Rare |
| `scene` | `liveKey`, `liveTitle`, `liveLinked` (library row receives live writes), `library { districtKey, siteKey }` (the live library row's own location), `districtKey`, `siteKey`, `tableKey`, `placementMode`, `lightingPresetKey`, `skyboxOverride`, `topFog`, `conditions` (scene condition ids; an empty list arrives as `{}`), `weatherOverride { rain, wind, thunder, untilDatetime }` (only while the Storyteller's weather is held), `weather { weather, rain, wind, thunder, indoors }` | Scene Apply, location/table/lighting/skybox/fog edits, weather changes, hour rollover (scheduled weather) | Low; bursts coalesce into one |
| `clock` | Anchor: `activeClock` (`scene`/`downtime`), `running`, `speed`, `catchUpToPresentDay`, `isPresentDay`, `scene`, `downtime`, `presentDay` datetimes; tonight's `dusk` / `dawn` datetimes (before sunrise: last night's) and the chronicle-scheduled `temperatureC` for the running clock's hour | Clock Apply or jump, pause/resume, speed change, scene Apply, phase change, **each hour rollover** | About once per narrative hour while running, plus edits |
| `soundscape` | `musicMode`, `musicMood`, `musicEnabled`, `musicSuppressed`, `locationMusic`, `location`, `siteSilent`, `featuredKey`, `featuredActive`, `sessionIntroKey`, `sessionIntroActive`, `lanes[] { id, volume, naturalVolume, ducked, active }` (ids `music`, `location`, `featured`, `rain`, `wind`, `thunder`; thunder's volume is a scale on each hit, active while thunder is on) | Any dashboard sound change (including volume drags), scene soundscape apply | Several per second at most while dragging a slider |
| `seats` | `seats[]` (five PC rows then four NPC rows: `seat`, `kind`, `tableSlot`, `isPresent`; PC: `playerId`, `charKey`, `absentFromSession`, `playingNpcKey`, `signal` (signal fire lit, read from the fire object via `O.GetSignalFireState`); NPC: `characterKey`, `slotEmpty`), `stage[] { characterKey, u, v, lightMode }`, `generics[] { characterKey, name }` (generic NPCs spawned this scene), `scatter[] { group, pcs[] { characterKey, slot }, npcs[] { characterKey, slot } }` (Scatter groups; empty unless Scatter is on), `spotlightOrder`, `spotlightFrontIndex` | Scene/table/seat changes through the Scenes panel, control board Apply/Clear and dashboard stage edits (`Sync.npcs`), generic NPC add/remove, Scatter moves from the dashboard, Spotlight shuffle and rotation, a signal fire lit or put out (candle click, debug seat row, dashboard `signalOff`) | Low |
| `rolls` | `pcs[]` (one per PC with a live roll, or `done` with their last finished roll, already broadcast, until they roll again (`storytellerRolls.pcDash` plus result and dice from the roll history; Broadcast again / Dismiss): `color`, `name`, `rollId`, `rollType`, `phase`, `initiator`, `label`, `pool` by dice kind, `difficulty`, `conditions` text, `result { resultClass, successes, margin, text }`, `pending` (`oblivHungerStain` / `brutalFailViolence` while the player chooses), `wpReroll` (a Willpower reroll is under way), `canModifyPool`, `dice[] { value, kind, selected }`), `storyteller { canInitiate, slots[] { index, label, rollType, phase, live, canBroadcast, pendingBroadcast, result, difficulty, pool, dice }, live }` (a confirmed drawer carries its finished roll from the Black seat's roll history until the drawer is cleared; the Rolls cell shows it as a foldable card with Broadcast / Dismiss; `live` is the Black seat's live NPC roll: the PC fields above plus `npcCharacterKey`, `slot`, `hint`, `actions` (which in-game panel buttons apply), `secret`, `quiet`), `werewolves` (NPC keys flagged `werewolf = true` in `lib/npcs_data`), `oblivionSeats` (PC seats with an Oblivion-Rouse bag) | Every roll state change (`RC.onRollStateChanged`), every Storyteller drawer save, and every dashboard roll command | Per roll step; die settles coalesce |

World topics (`phase` … `rolls`) are built by `dashboard/world_snapshot.ttslua` and sent together about 0.25 s after the first change in a burst. Optional fields are omitted when TTS holds no value (Lua `nil`).

### Seat words — keep them apart

`isPresent` is **narrative** presence: a connected player who is seated but out of the scene. `absentFromSession` is **connection** state: the PC's client was not connected at the last blindfold checkpoint. Label them differently in any UI ("Not in scene" vs "Disconnected"). See `docs/solutions/seat-occupancy-and-connection.md`.

### Not broadcast

- **Clock minutes.** Run the clock locally with `clockNow(clock, Date.now())`; it advances `speed` narrative minutes per real minute from the anchor and stops at the present day during catch-up.
- **Storyteller-panel UI state:** library row selection, pickers, drafts, which TTS panel is open.
- **Catalog and library contents:** scene library rows, site/district/table catalogs, NPC records beyond seat and stage placement. Fetch these on demand (catalog JSON routes, execute-lua) when the view opens.
- **Raw `playerData`** — only in the full `GlobalDashboardPcSheetSnapshot`.
- **Roll options** (the TTS options modal's toggles and numbers) — fetched when the Storyteller opens the pop-up (`GlobalDashboardRollOptions`).

## 3. How to listen

| Need | Use |
| --- | --- |
| World slices in a React view | `const world = useWorldState()`. On mount, if a slice you need is `undefined`, call `refreshWorldSnapshot()` once (it fills only missing slices) |
| The current narrative time | `clockNow(world.clock, now)` on your own animation or minute timer — browser-side only, never a TTS call |
| Seat data | Follow `PcSheetTab.tsx`: fetch the full snapshot once, then merge `pcSeat` pushes with `mergeSeatPush` |
| Any other topic | `subscribeTtsEvents(listener)` in a `useEffect`; return its unsubscribe |
| A notice-only topic (`projects`) | Refetch that domain's snapshot, and only while the view is mounted |
| `reload` | Clear local copies and refetch once (the world store clears itself) |

All subscribers share one `EventSource`; the browser reconnects it on its own and the server replays its cache, so a reconnect needs no special handling.

## 3a. Sending commands

Commands use execute-lua into a `GlobalDashboard…Apply` entry, behind the shared serial queue (`createApplyQueue` in `src/client/applyQueue.ts`): one call in flight, clicks made meanwhile go in the next batch. Every entry starts with the load guard and replies `{ ok, error? }`.

- **PCs tab:** `GlobalDashboardPcSheetApply` replies with a fresh sheet snapshot.
- **Scenes tab:** `GlobalDashboardScenesApply` (`dashboard/scenes.ttslua`) replies only `{ ok, error? }`; the world push brings the new state back. Panels read the sender from `ScenesCommandContext` (the table's queue on the Scenes tab, or a scene draft's editor in a preview); `useScenesCommand` throws without one. `coalesceCommands` drops superseded lane volumes and real-time settings from a batch, and dragged sliders hold their local value for 1.5 s so the echo does not jump under the pointer. Ops are listed at the top of `dashboard/scenes.ttslua`. Before the apply queue, the stage queue (`scenesPanel/queue.ts`) holds stage board edits: `commandKind` marks stage changes and Scatter group moves `queue`, and they wait in the `StageQueue` pop-up over the stage board's bottom-left until Send (one entry per target, labelled from the pushed world by `queueLabels.ts`); the pop-up shows only while something waits. Stage Clear and Reset are `flush` (they send the queue first in the same batch); every other command is `direct` and goes at once.
- **Signal fires:** a PC seat row with `signal` lights up the Scenes tab: the seat pulses with a flame button, an amber glow pulses round the screen edge, a banner over the stage names the PC with **Put it out**, and a three-tone chime plays when a signal is lit and every minute while any stays lit (`scenesPanel/signal.tsx`; the browser plays sound only after one click on the page). The flame button and **Put it out** send `signalOff { color }`, which calls `GlobalToggleSignalFireState` only when that fire is lit.
- **Scene edits from the Scenes tab:** `location`, `skybox` (`"none"` = the Site's sky), `topFog`, `lighting` (Admin Dark / Standard / Bright), `table` (including `"Scatter"` and the `"Table B"` family) and `conditions` go through the `StorytellerScenesPanel.setLive*` setters the in-game panel uses. `weatherOverride` holds rain / wind / thunder in `gameState.weatherOverride` until the next dawn (`ChronicleWeather.applyScheduledWeather` plays it instead of the schedule and clears it once the scene clock passes dawn); `{ release = true }` returns to the schedule. `memoriam` hands the dashboard-built payload (same shape as the in-game Memoriam modal; the panel list comes from `data/scene-catalogs.json` `memoriamPeriods`, generated from `lib/skyboxes_catalog.ttslua`) to `Memoriam.applyEnter`; `leaveMemoriam` calls `Memoriam.applyExit({ mode = "restore" })`, which goes back to the scene the Memoriam interrupted (`gameState.memoriam.returnSceneKey`, captured only when it started from Main with a scene on the table) while that scene is new or ongoing, and otherwise to Downtime with no scene. The scene push carries `memoriamReturnTitle` for that scene, so the dashboard labels the button Return ▸ or Downtime ▸.
- **Scene library:** the dashboard keeps the master copy in `data/scene-library.json` (git-ignored, backed up like the scene deck; server store `src/server/dataFileStore.ts`, route `/api/scene-library`, client store `src/client/sceneLibrary.ts`). Rows keep TTS's own shape (`title`, `placementMode`, `receivesLiveWrites` → `linked`, `status`, `sessionScene`). **Status** (TOR-705) is `new` (also a row without one), `ongoing`, `ended` or `template`. TTS sets `ongoing` when a scene is played and `ended` on End Scene; the dashboard sets the rest through `setSceneStatus { key, status }` (`ended` is refused for the scene on the table: use End Scene). `upsertScene` takes a status only for a new row and never changes an existing row's, and `mergeFromTts` always takes TTS's status, so neither side overwrites the other with a stale copy. TTS refuses to play templates and ended scenes and hides them from the in-game Scenes panel (`SceneLibrary.playableOrder`). The dashboard is the only editor of library rows: the in-game panel only plays them, `upsertScene` refuses a row TTS could not play (`SceneLibrary.validateRow`: clock, lighting preset, numbered chairs — [Scene Import Guide](Scene%20Import%20Guide.md)), and the snapshot leaves out E2E fixture rows (`e2e_*`). On the dashboard (`scenesPanel/sceneStatus.ts`), ongoing scenes always sit on the deck (green) beside starred new scenes and templates (gold); templates show in brackets and play as a new copy titled with the night (`"Elysium (Oct 12)"`); ended scenes wait in the Play a Scene window's archive, where their status can be changed back. It is copied in from TTS once through `GlobalDashboardSceneLibrarySnapshot(keysJson?)` (`dashboard/scene_library.ttslua` `snapshot`), which also serves the write-back: while a linked scene is on the table, and once more when the table switches or ends a scene or the link changes, the Scenes tab reads that row back (`scenesPanel/useLibraryActions.ts`, merge rules in `scenesPanel/library.ts` `mergeFromTts`). These write-back reads take TTS's copy even when the row is no longer linked: TTS writes the leaving scene one last time as it unlinks (Dashboard stage edits only run a narrow sync, and the running scene clock), so that last write is the only copy of where the scene was left. Play from the picker or a preview sends `upsertScene` (the row; only its title when it is the linked row on the table) then `playScene` in one batch. Switching back to an ongoing scene happens at once (`entryPlan` in `scenesPanel/sceneStatus.ts`): at the scene's own time, catching up at ×5 when that time is from present day's night and ×2 from an earlier night (at Now if the scene has no time). Any other scene first opens the scene timing menu (`useSceneEntry` / `SceneTimingRing` in `scenesPanel/glance.tsx`, helpers in `scenesPanel/sceneClock.ts`): present day ("Now") and, when the scene has a time of its own, that time, each with a strip of start offsets (0 to 240 minutes; hovering previews the time). `playScene { key, from: "scene" | "present", plusMinutes, pace: "x2" | "x5" }` starts that many minutes after the scene's time or present day (`present` moves present day on; a scene start later than present day moves it on too), and real time runs at ×2, or with `x5` at ×5 until it reaches present day and then ×2 (`applyDashboardPace` in `core/present_day_clock.ttslua`). The menu picks ×5 for a start earlier on present day's night (hours before noon belong to the evening before) and ×2 otherwise. `deleteScene` refuses the scene on the table; `unlinkScene` stops live writes; `forkScene { newTitle, oldTitle? }` keeps a snapshot in the old row (optionally renamed) and the table carries on in a new linked row, which becomes `lastAppliedKey`. Preview drafts live in the scene deck's `previews` section until Save, On deck, Play Scene or Discard; their panels rewrite the draft through `applyToDraft` instead of sending to TTS.
- **Stage edits (TOR-685):** `stage { changes }` carries a per-NPC delta in stage (u, v): `{ u, v, lightMode? }` (`OFF` / `STANDARD` / `SPOTLIGHT`; a new NPC defaults to `STANDARD`, a moved one keeps its light) or `{ remove = true }`. `stage { clear = true }` empties the stage and destroys the scene's generic NPCs; `stage { reset = true }` goes back to the linked library row's placements. All three call `StageApply.applyStageChanges` in `core/npc_stage_apply.ttslua`: seat darkening for seated NPCs placed on the stage (and relighting the seat whenever they leave it, lit or not), then `Sync.npcs` with reason `stage_apply` so figurines glide and spotlight tokens on the Stage Control board follow (`core/stage_tokens.ttslua`). Queued stage edits merge into one `stage` write per Send (`coalesceCommands`), so their figurines move in one animation; Clear and Reset flush. `scatterPlace { characterKey, kind = "pc" | "npc", group? }` moves a character between Scatter groups (no `group` takes an NPC off; PCs always need one). `genericAdd { keys, labels }` spawns generic NPCs with the given player-facing names (`GenericNpcs.importNamed`); `genericRename { key, name }` renames one already spawned (`GenericNpcs.rename`: membership `displayName`, roster `fullName`, figurine and spotlight-token names). Both wait in the stage queue: a roster click queues `genericAdd` plus a `stage` placement on a free slot near the stage's top-left corner (the merged stage write lands after the add in the same Send), renaming a queued generic rewrites its `genericAdd` label, and removing it from the stage or the queue drops both.
- **Seat drags:** on the live table (not scene previews, not Scatter) the seat row is drag and drop (`Seats` `seating` in `scenesPanel/sketch.tsx`). A seated character drags as a token (`SEAT_DRAG_TYPE`, plus `NPC_DRAG_TYPE` for NPCs): onto another chair it sends `seatMove { seat, chair }` (`SeatMoves.moveToChair` in `core/seat_moves.ttslua` swaps `seatSlots[*].tableSlot` with whoever holds that chair); a seated NPC dropped on the stage is an ordinary queued `stage` placement, and the board shows their seat dark until Send. A roster NPC dropped on an empty chair, or a stage token dropped on an empty chair or the NPC's own (`chairAt` in `scenesPanel/stageEdit.tsx`, cells carry `data-chair`), sends `seatNpc { characterKey, chair }`: `SeatMoves.seatNpc` keeps the NPC's own NPC seat key or takes a free one, sets the chair, lights the seat, removes their stage placement, and drops their queued stage edits (`withoutQueuedStage`). Both are `direct`, refuse while dice are on the table (`RSL.alertAndBlockIfDiceOnTable`), never move a character to another seat key, re-pick the `Table B` variant for the new occupancy, then run one forced `Sync.npcs` (its layout commit re-lays the table). Generic NPCs do not take chairs.
- **Rolls (TOR-686):** `GlobalDashboardRollsApply` (`dashboard/rolls.ttslua`, ops listed at the top) never waits in the Send queue: dice are live play, so each click leaves at once through its own apply queue (`useRollsQueue` in `scenesPanel/ScenesPanel.tsx`, transport in `scenesPanel/rolls/bridge.ts`). Ops call the roll controller, the Storyteller drawers and the HUD handlers the in-game roll panels use; the `rolls` slice brings the result back. Picking a difficulty on a PC roll still in setup also opens it to the player (the approval). The options pop-up reads its starting values from `GlobalDashboardRollOptions(color)`; a roll-type change is sent at once (`rollType`) and the values re-read. `hunt { color, flavor, intensity, margin }` shows the hunt's resonance on the roll result banner in TTS and records it on the PC (`playerData[pid].huntResonance`, read back on the PC seat snapshot).
- **Compulsion badge:** the PC seat snapshot carries `compulsion = { type, n }` while a Compulsion card is selected in front of the seat (`Compulsions.activeForColor` in `core/compulsions.ttslua`: GM Notes type, `Clan` for the clan card, variant 1-4; cached per seat and updated, with a `DashPush.seat`, when a card is selected or returned). The Scenes tab shows it as a red tag on the seat (`scenesPanel/compulsionBadge.tsx`), mapping `Clan` through the PC's clan (the Compulsion whose entry names that `clan`); hovering shows the card's Influence / Burden / Catharsis from the author's git-ignored `data/compulsions.jsonc` (`/api/compulsions`, comments stripped server-side, validated by `parseCompulsions` in `src/shared/compulsionText.ts`). Each Compulsion lists four variants whose `card` is the GM Notes N.

## 4. Design checklist for a new dashboard view

1. **List the data the view shows** and find each item in § 2. If everything is there, build on the existing topics.
2. **Never add a timer that calls execute-lua.** One fetch on open is the ceiling. If a value must move continuously (like the clock), push an anchor and animate it in the browser.
3. **Handle missing slices.** After a dashboard server restart the cache is empty until each slice next changes; show a quiet loading state and call `refreshWorldSnapshot()`.
4. **Handle `reload`.** TTS reloads during play (Save & Play, loading a save). The view must recover without a page refresh.
5. **Your own writes:** if the view sends a command and gets a fresh snapshot back, it may ignore pushes for that domain while the command is in flight (the PCs tab does this), because TTS pushes before it answers.
6. **Keep words honest:** occupied vs present vs disconnected (above).

## 5. When the data you need is not broadcast

Prefer, in order:

1. **Add a field to an existing slice or the seat snapshot.** Seat data goes in `snapshotSeat` (or a sheet extension's `snapshotFields`); it rides `Sync.player` automatically. World data goes in the matching `world_snapshot` builder. Check that the mutation path already marks that slice (Live Push Channel § 3a); add a `DashPush.markWorldDirty` call only where it bypasses `UpdateUIDisplays`.
2. **Add a world slice** when the data is a separate concern with its own triggers: add the builder and its name to `W.SLICES`, mark it at its mutation/reconcile sites, add the client type and topic to `worldState.ts`, and add tests.
3. **Fetch on demand** when the data is large, rarely changes, or is only needed while one view is open.

Rules for any change on the TTS side: Global-only modules (never `require("dashboard.*")` from object scripts); no marks in per-frame or per-tick paths; payloads stay flat with structured data as the `json` string field; update this guide, Live Push Channel § 3, and the Lua half's Linear issue plus a Pending Author Verification row.

## 6. Checking it live

- **What did TTS last send?** Open `http://127.0.0.1:8788/api/tts/cache`.
- **Is TTS sending at all?** Turn on Trace Sync in TTS: each send logs `DashPush.seat` or `DashPush.world` with `sent` / `skipped` and the byte count.
- **Server changes need a restart** (`npm run dev` in `.dev/storyteller-dashboard/`); Lua changes need Save & Play.
- If Trace Sync says `sent` but nothing arrives, suspect a nested table in the message (TTS drops those silently) or the server not connected to the gateway (`GET /api/tts-bridge-status`).
