## The short version

Today the mod and the dashboard get asset URLs in **six different ways**. Almost every hosted file lives on one of two hosts:

- **Steam Cloud** (`steamusercontent-a.akamaihd.net/ugc/...`). About 980 of the roughly 1,000 URLs in the repo point here. You upload these files through the TTS Cloud Manager, so each one has a URL that cannot be predicted in advance.
- **GitHub raw** (`raw.githubusercontent.com/Eunomiac/toronto-rising-tts/master/...`). Used for all NPC art, plus a fallback for a few dashboard site cards. The URL is predictable from the file path, but the file has to be committed **and pushed** before TTS can load it.

The six methods are:

| # | Method | In plain terms | Main users |
| --- | --- | --- | --- |
| 1 | **Typed by hand into code** | A Steam URL is pasted straight into a Lua table. | Storyteller dice, companion toggle, NPC spotlight AssetBundle, Blood Potency decals, relationship portraits |
| 2 | **Imported from a Google Sheet** | You paste the Steam URL into a sheet; an npm script copies the sheet into a Lua catalog or JSON file. | Skyboxes, site cards (one of two paths) |
| 3 | **Synced from Steam Cloud** | A script reads your TTS Cloud Manager folders directly and writes the URLs into the save and/or a Lua catalog. | Memoriam panels and blindfolds, site cards (the other path), Scatter overlay, character sheet page art |
| 4 | **Built from a GitHub path** | A script writes `base URL + file path + ?v=<hash>` so the URL changes whenever the art does. | NPC figurines and spotlight tokens, dashboard site-card fallback |
| 5 | **Stored only in the save** | The URL was set in TTS (Cloud Manager upload, object import, decal upload) and never leaves the save file. Lua refers to the image **by name** or to the object **by GUID**. | Most HUD images, all dice/candle/emitter models, soundscape audio, district cards, map panel |
| 6 | **Local files served or bundled** | No hosted URL at all; the dashboard serves repo files from disk or bundles its own copies. | Dashboard NPC headshots, PC sheet art, dice faces, badges, district map |

Method 5 is the largest. Lua code almost never holds a URL; it holds a **name** like `siteCard_AnarchBar` and lets TTS look that name up in the save's registered Custom UI assets. The real question for harmonization is therefore mostly "how does each name get its URL into the save", which is where methods 1 to 4 compete.

## Part 1 — URLs held in TTS Lua code

These are the only places where Lua code itself contains or builds a URL. All files listed here are committed to git.

### 1.1 `lib/cloud_catalog.ttslua` — Memoriam panels and site cards (method 3)

- **What:** 366 Steam URLs in a global `Cloud` table. `Cloud.MemoriamPanels` holds the four panel images for each Memoriam skybox (`<skyboxKey>_a` to `_d`). `Cloud.Sites` holds site card images.
- **How the URL arrives:** generated by `.tools/cloud-asset-sync.js` (jobs `memoriamPanels` and `cloudSitesCatalog` in `.tools/cloud-asset-sync.jsonc`). The script reads the TTS Cloud Manager index for the `Memoriam` and `Sites` folders. The file header says it is auto-generated.
- **Run by:** `npm run cloud-asset-sync:catalog`, or the Full build (`cloud-asset-sync -- --yes-purge`).
- **Consumer:** `lib/constants.ttslua` (`applyMemoriamCloudPanelUrls`, around line 2872) copies the panel URLs into `C.MemoriamSkyboxes`. `core/scenes.ttslua` applies them with `Backgrounds.setCustomURL`.
- **Note:** nothing in Lua reads `Cloud.Sites`. `C.cloudCatalogURL()` exists but has no callers.

### 1.2 `lib/skyboxes_catalog.ttslua` — table skyboxes (method 2)

- **What:** 105 Steam URLs. `Skyboxes` (keyed, with display names), `GenericSkyboxes` (10 random backgrounds), and `MemoriamSkyboxes` metadata (no URLs; those come from 1.1).
- **How the URL arrives:** you type the Steam URL into the Toronto Rising API sheet (named ranges `SKYBOXCSV`, `SKYBOXGENERICCSV`, `SKYBOXMEMORIAMCSV`). `.dev/scripts/import_skyboxes_from_sheet.js` downloads the CSV and writes this file.
- **Run by:** `npm run skyboxes:import` (also part of the Full build).
- **Consumer:** `C.resolveSkyboxURLFromKey`, `C.resolveSkyboxURLForSite`, `C.pickRandomGenericSkyboxURL` in `lib/constants.ttslua`; applied by `core/scenes.ttslua` and `core/memoriam.ttslua`.

### 1.3 `lib/npc_art_urls.ttslua` — NPC figurines and spotlight tokens (method 4)

- **What:** about 420 NPC rows. Each has figurine front/back and token front/back URLs, all built from one `BASE` string at line 6:
  `https://raw.githubusercontent.com/Eunomiac/toronto-rising-tts/master/assets/images/NPCs/`
  plus `<Catalogued|Generic|Memoriam>/<key>.webp?v=<hash>` or `Tokens/<key>.front.webp?v=<hash>`.
- **How the URL arrives:** generated by `.dev/storyteller-dashboard/scripts/npc-art/generate.ts`, which also draws the token images from the figurines. The `?v=` value is a content hash, so TTS re-downloads only when the art changes.
- **Run by:** `npm run npc-art:generate` (also part of the Full build).
- **Manual step:** commit and push to `master` before TTS can load new art. The script warns if you have not.
- **Consumer:** `core/npc_spawn.ttslua` (figurine spawn data), `core/stage_tokens.ttslua` (`setCustomObject` on tokens), `lib/npcs_data.ttslua` (generic NPC list).
- **Side effect:** the same script also rewrites the save's roll-banner Custom UI assets (named after each character key) to point at these GitHub URLs. See Part 2.

### 1.4 `lib/blood_potency_constants.ttslua` — Blood Potency decals (method 1, script-assisted)

- **What:** 29 Steam URLs in `BPC.BloodPotencyDecalUrls` (`bloodSurge*`, `mending*`, `discBonus*`, `discReroll*`, `baneSeverity*`).
- **How the URL arrives:** you upload the decals in TTS (Mod → Decals). `npm run custom-ui-assets:extract-bp-decals` reads them from a save copy and writes a Lua snippet to the gitignored `.dev/custom-ui-assets/bp-decal-urls.lua`. You then **paste** that snippet into the constants file by hand.
- **Consumer:** `lib/blood_potency_decals.ttslua` builds a `setDecals` payload, called from the character sheet object script `ui/ui_csheet_core.ttslua`.

### 1.5 `lib/companion_toggle.ttslua` — companion toggle faces (method 1)

- **What:** 4 Steam URLs in `TOGGLE_FACE_URLS` (around line 166): enabled and disabled faces for the Red and Brown companion toggle tiles.
- **How the URL arrives:** typed by hand. If missing, the code falls back to reading the live object's own image URLs.
- **Consumer:** `setToggleTokenFace()` calls `setCustomObject` + `reload()`.

### 1.6 `core/st_dice.ttslua` — Storyteller dice (method 1)

- **What:** 6 Steam URLs in `DIE_ART` (around lines 30–55): d10 face sheets for Normal, Hunger, Rouse, Oblivion-Rouse, Werewolf, and Rage dice.
- **How the URL arrives:** typed by hand (same art the retired Storyteller dice bags used).
- **Consumer:** `dieData()` puts the URL in `CustomImage.ImageURL` for `spawnObjectData`.

### 1.7 `lib/npcs_light_spawn_defaults.ttslua` and `core/debug.ttslua` — NPC spotlight AssetBundle (method 1, duplicated)

- **What:** one Steam AssetBundle URL for the NPC spotlight effect.
- **How the URL arrives:** typed by hand in **two** places: `lib/npcs_light_spawn_defaults.ttslua` line 57 (used by `core/npc_spawn.ttslua` and `core/spotlight.ttslua`) and `core/debug.ttslua` line 1621 (`SPOTLIGHT_ASSETBUNDLE_URL`, used only by a debug audit). A third reference copy sits in `.dev/NPC Object Spawning & Spotlighting/NPC Light Object Data.jsonc`.

### 1.8 `lib/custom_ui_upload_manifest.ttslua` — upload staging (method 5 helper)

- **What:** a committed empty stub. The image-folder upload pipeline overwrites it locally with `file:///` URLs so a debug command can spawn upload tokens in TTS (see Part 4, "Image-folder upload").
- **Consumer:** debug code only (`DEBUG.spawnCustomUiUploadBatch` in `core/debug.ttslua`).

### 1.9 JSON files under `lib/json/`

| File | URLs | How they arrive | Who reads them |
| --- | --- | --- | --- |
| `Site Cards.json` | 167 Steam URLs as `siteCard_<key>` rows | `npm run site-cards:import -- --range SITECARDCSV` (Google Sheet). The same run also rewrites every `siteCard_*` row in the save. | **No Lua code.** It is a record of the last sheet import. |
| `PC_Relationship_Images.json` | 64 Steam URLs (relationship portraits and dividers for character sheet Page 4) | Typed by hand; no generator found. | `npm run custom-ui-assets:merge-object-assets` (Full build) copies them into the Page 4 sheet objects' Custom UI assets. The dashboard's `fetch-sheet-assets.mjs` also reads it. Lua only uses the names. |

### Files that look URL-related but hold none

- `lib/soundscape_catalog.ttslua` holds AssetBundle **effect names and indexes**. The audio AssetBundle URLs live only on the emitter objects in the save (Part 3).
- `lib/locations_catalog.ttslua` (from `npm run locations:import`) holds skybox **keys**, not URLs. Its site and district keys are used to build `siteCard_<key>` and `districtCard_<key>` names.
- `lib/tarot_objects.ttslua`, `objects/*.ttslua`, and the dashboard Lua bridge in `dashboard/*.ttslua` contain no URLs.

## Part 2 — Images referenced by name (URL lives in the save)

Most HUD and character sheet images are never URLs in code. XML and Lua use `image="<name>"`, and TTS looks the name up in the save's **Custom UI assets**: either the global list (Modding → Custom UI Assets) or a specific object's own list. Many names are built at runtime from a key.

The table shows where each family of names is built in code, and how its URL gets into the save.

| Name pattern | Built in | How the URL gets into the save |
| --- | --- | --- |
| `siteCard_<siteKey>` | `core/hud_blindfold.ttslua`, `core/hud_player.ttslua` | **Two competing writers:** the Google Sheet import (`site-cards:import`) and the Steam Cloud sync job `siteCards` (Full build). Whichever ran last wins. |
| `districtCard_<key>`, `mapOverlay_<key>` | `core/hud_blindfold.ttslua`, `core/hud_player.ttslua` | Manual uploads only. No script produces these. |
| `memoriamBlindfold_<skyboxKey>` | `core/memoriam.ttslua` | Steam Cloud sync job `memoriamBlindfolds` (folder `Memoriam/Blindfolds`) |
| `scatterModeControlPC_<occupant>`, `scatterGroup*` | `core/scatter_mode.ttslua` | Steam Cloud sync job `scatterOverlay` (folder `HUD/Scatter Overlay`) |
| Character keys (roll banner figures) | `core/roll_ui.ttslua` | `npc-art:generate`, pointing at the GitHub NPC art (1.3) |
| `<name>Portrait`, `divider_*` (Page 4) | `lib/csheet_page4_xml.ttslua` | `custom-ui-assets:merge-object-assets` from `PC_Relationship_Images.json` (1.9) |
| Character sheet Page 1, 2 and 6 art (`dot_*`, `box_*`, Blood Potency stat images, `navigate_*`) | static XML templates | Steam Cloud sync jobs `csheetPage1Overlays`, `csheetPage2Assets`, `csheetPage6Assets` (object assets, by sheet GUID). Page 1 and 2 decal rows can also come from `custom-ui-assets:merge-bp-decals-into-csheets`. |
| `overlay_sessionStartSplash_N`, `overlay_sessionNumber_N`, `overlay_sessionTitle_N` and other `overlay_*` | `core/phases.ttslua`, `core/hud_overlays.ttslua`, `lib/condition_effects.ttslua` | Manual uploads. `core/phases.ttslua` checks whether the name is registered and hides missing art. |
| `dieFace_<kind>_<face>` | `lib/dice_kinds.ttslua`, `core/roll_ui.ttslua` | Manual uploads |
| `project_die_*`, `court_project_*` | `core/projects.ttslua` | Object assets on character sheet Page 5 (manual) |
| Static names in `ui/**/*.xml` (`mapBase`, `pin_*`, `toggle_*`, `refPanel_*`, `buttonCamera_*`, `nameLabel_*`, …) | XML templates, embedded into `lib/ui_global_xml_docs.ttslua` | Manual uploads, either through the image-folder pipeline or the Cloud CSV tasks (Part 4) |

**Copying names around at runtime.** `core/global_script.ttslua` (around lines 1047–1183) backs up the full global list with `UI.getCustomAssets()`, swaps in a slim list for joining players, and restores it later (TOR-439, the join-minimal HUD work). It moves existing URLs; it never creates new ones.

**Committed source art.** The repo tracks about 2,000 images under `assets/images/` (`NPCs` 1,348, `Map Panel` 406, `Sites` 168, `Right Sidebar` 48, `Districts` 36, `Dice SVGs` 12, plus a few borders and overlays). Only `NPCs/` is loaded by TTS from these paths. For the other folders, TTS uses separately uploaded Steam copies registered by name. This survey did not check whether the committed files match what was uploaded.

## Part 3 — URLs authored directly on table objects in the save (method 5)

These URLs were set in TTS (Custom Object import, Workshop objects) and exist only in the save's object data. No repo code writes them. Lua finds the objects by GUID or tag and calls effects or state changes on them.

The `.tts/objects/*.data.json` dumps (gitignored, written by the TTS Tools extension for scripted objects) show the URL fields:

| Object family | URL fields |
| --- | --- |
| Standard, Rouse, Oblivion-Rouse, Blood Surge dice (per player colour) | `MeshURL`, `DiffuseURL`, `NormalURL`, `ColliderURL`, `ImageURL`, `ImageSecondaryURL` |
| Signal Candles (per colour), Turn Swivel Light | `AssetbundleURL`, `AssetbundleSecondaryURL` |
| Soundscape emitters (Featured A/B, Location A/B, Music A/B, Weather Rain/Thunder/Wind) | `AssetbundleURL`, `AssetbundleSecondaryURL` — the soundscape audio lives here |
| Character sheet pages (5 PCs × 8 pages) | `ImageURL`/`ImageSecondaryURL` for the page itself, plus about 125 object Custom UI asset `URL` rows per PC |
| Companion figurines (Robin, Sylvain), Tarot Deck Button | `ImageURL`, `ImageSecondaryURL` |

Every other table object (fog, tables, chairs, map, and so on) is the same story but has no script, so it is not dumped to `.tts/objects/`. Use `npm run tts-save:extract-entities` for the full list.

## Part 4 — Tooling that produces or rewrites URLs

Only the **Full build** (`npm run build:full`) runs URL tools automatically. The Main and XML builds do not change any URLs.

| Tool (npm command) | Reads from | Writes to | Host | In Full build? |
| --- | --- | --- | --- | --- |
| `skyboxes:import` | Google Sheet (API sheet, named ranges) | `lib/skyboxes_catalog.ttslua` | Steam (URLs typed in sheet) | Yes |
| `site-cards:import -- --range <Range>` | Google Sheet (`Name,URL`) | `lib/json/Site Cards.json` **and** every `siteCard_*` row in the live save (no backup) | Steam | No |
| `cloud-asset-sync` (8 jobs in `.tools/cloud-asset-sync.jsonc`) | TTS Cloud Manager index via Steam | Live save (global and per-object Custom UI assets) and `lib/cloud_catalog.ttslua` | Steam | Yes (`--yes-purge`) |
| `tts-cloud:export` + `custom-ui-assets:purge` + `custom-ui-assets:add-csv` (VS Code tasks **[Assets 1–3]**) | TTS Cloud folder → CSV | Live save Custom UI assets | Steam | No (manual version of `cloud-asset-sync`) |
| `custom-ui-assets:pipeline` (image-folder upload) | Local image folder | `file:///` manifest → you run `DEBUG.spawnCustomUiUploadBatch()`, then Cloud Manager **Upload All Loaded Files** → merge scrapes the new Steam URLs back into the save | Steam | No |
| `npc-art:generate` | Committed figurines in `assets/images/NPCs/` | Token images, `lib/npc_art_urls.ttslua`, `lib/npc_overrides.ttslua`, roll-banner rows in the live save | GitHub raw | Yes |
| `custom-ui-assets:merge-object-assets` | `lib/json/PC_Relationship_Images.json` | Page 4 sheet object assets in **`.dev/TS_Save_230.json`** (a stale local copy, not the live save) | Steam | Yes |
| `custom-ui-assets:extract-bp-decals` | Save `DecalPallet` (in `.dev/TS_Save_230.json`) | Lua snippet to paste into `lib/blood_potency_constants.ttslua` | Steam | No |
| `custom-ui-assets:merge-bp-decals-into-csheets` | Save `DecalPallet` | Page 1/2 sheet object assets in `.dev/TS_Save_230.json` | Steam | No |
| `dashboard:scene-catalogs` | Lua catalogs + live save `siteCard_*` / `districtCard_*` rows | `.dev/storyteller-dashboard/data/scene-catalogs.json` | Steam, or GitHub fallback | Yes (via `locations:import`), and on every dashboard `npm run dev` / `build` |
| `fetch-sheet-assets.mjs` (dashboard folder, run by hand) | Steam URLs in `.tts/objects/*` and `PC_Relationship_Images.json` | Local copies in `.dev/storyteller-dashboard/assets/{sheet,dots,portraits}` | Steam → local | No |

Configuration: `tts-assets.config.json` (`savesDir`, `defaultSaveName`, `backupDir`) is read by most save writers. The Steam Cloud root folder actually used is `CLOUD_ROOT` in `.tools/tts-cloud/config.js`; the `cloudRoot` key in `tts-assets.config.json` is never read.

Read-only reporters (no URLs written): `tts-save:extract-assets`, `tts-save:extract-entities`, `custom-ui-assets:probe-urls`, `.tools/custom-ui-assets/list-custom-ui-assets-from-save-name.js`.

## Part 5 — Storyteller Dashboard

The dashboard never reads TTS's local image cache and has no image proxy. What it sends to TTS is always a **key** (skybox key, site key, character key, portrait key), never a URL.

| Feature | Where the image comes from | Shared with TTS? |
| --- | --- | --- |
| NPC headshots, roster tokens, crop editor (`headshots/*`, `glance.tsx`) | Server route `/figurine-images/<key>.webp` reads `assets/images/NPCs/*` straight from disk (method 6) | **Same files**, different delivery: TTS loads them from GitHub raw after a push; the dashboard shows them immediately. |
| Location panel site card (`glance.tsx`, `LocationPanel`) | `sites[].cardUrl` in `data/scene-catalogs.json`, which the browser loads directly | **Same Steam URLs** for 170 sites (copied from the save's `siteCard_*` rows). 6 sites (`HockeyHallOfFame` and five `Warrens*`) use a GitHub fallback (`.../refs/heads/master/assets/images/Sites/<key>.webp`) that TTS has no copy of. 10 sites have no card anywhere. |
| District cards | `districts[].cardUrl` (36 Steam URLs) is generated but **never read** by the client. | — |
| District map picker | Dashboard's own `assets/scenes/districtMap.webp` via `/scenes-assets/` | Separate file from TTS's `assets/images/Map Panel/mapBase.webp` |
| Skyboxes and Memoriam panels | Not displayed; the dashboard only lists keys and display names. | TTS keeps the URLs. |
| PC sheet art (Pages 1–6), tracker boxes, Hunger dot | Dashboard's own `assets/**` via `/pc-sheet-assets/` | Part are **frozen copies** of TTS Steam art downloaded by `fetch-sheet-assets.mjs`; the rest (other dots, boxes, buttons, texture, fonts) exist only in the dashboard. They do not update when the Cloud art changes. |
| Page 4 relationship portraits | 28 local copies in `assets/portraits/`, bundled by Vite | Frozen copies of `PC_Relationship_Images.json` portraits (which has 64 rows). The dashboard sends only the portrait key. |
| Rolled dice faces | `public/icons/dice/*.svg` | Different art from TTS dice and from `assets/images/Dice SVGs/` |
| Tier badges, toast icons, inline UI glyphs | Dashboard's own `assets/badges`, `assets/icons`, inline SVG | Dashboard only |
| Term tooltip images | Pasted by you into the gitignored `data/term-images/` | Dashboard only |
| Generate NPC tab | OpenAI image API, returned as a `data:` URL; not saved | Dashboard only |
| Location text, weather | Browser fetches Google Sheets CSV (`gviz/tq`) at runtime | Same sheets TTS bakes into Lua at build time |

One dashboard asset feeds TTS art: the BebasNeue font in `.dev/storyteller-dashboard/assets/fonts/` is used by `npc-art:generate` to draw names on TTS spotlight tokens.

## Part 6 — Overlaps, drift, and loose ends

These are the places where the current methods disagree or have gone stale. They are listed as findings, not fixes.

1. **Site cards have three writers.** The Google Sheet import, the Steam Cloud sync job `siteCards`, and the manual **[Assets 1–3]** tasks all write `siteCard_*` into the save. The Full build runs only the Cloud sync, so in practice Steam Cloud wins. `.dev/custom-ui-assets/README.md` still names the sheet as the source of truth. `lib/json/Site Cards.json` and `Cloud.Sites` are both unread records of different uploads (their URLs differ, for example `AnarchBar`).
2. **Dashboard site cards lag one Full build.** `dashboard:scene-catalogs` runs (inside `locations:import`) before `cloud-asset-sync` updates the save, so newly uploaded cards reach the dashboard only on the next run.
3. **The relationship-portrait merge in the Full build writes to a stale save copy.** `custom-ui-assets:merge-object-assets`, both Blood Potency decal scripts, and the `tts-save:*` reporters default to `.dev/TS_Save_230.json` (a gitignored copy last written 2026-09-05), not the live save.
4. **A save folder that no longer exists is hard-coded.** `D:/OneDrive/Documents/My Games/Tabletop Simulator/Saves` appears in `merge-custom-ui-assets-from-save-name.js`, `prune-custom-ui-assets-from-save-name.js`, `list-custom-ui-assets-from-save-name.js`, and `extract-bp-decal-urls-from-save.js`. These ignore `tts-assets.config.json`.
5. **Two GitHub URL forms.** NPC art uses `.../master/...` with a `?v=` cache-buster; the dashboard site-card fallback uses `.../refs/heads/master/...` with no cache-buster.
6. **The spotlight AssetBundle URL is typed twice in code** (`lib/npcs_light_spawn_defaults.ttslua` and `core/debug.ttslua`), plus a reference copy in `.dev`.
7. **Hand-maintained URL lists with no generator:** `PC_Relationship_Images.json`, `BPC.BloodPotencyDecalUrls` (script-assisted paste), `TOGGLE_FACE_URLS`, `DIE_ART`.
8. **Names with no producer.** `districtCard_*`, `mapOverlay_*`, `dieFace_*`, session overlay art and most static HUD names come only from manual uploads; no script records or checks them.
9. **Dashboard copies drift from TTS.** PC sheet art and portraits are one-time downloads; the district map and dice are separate art sets.
10. **Two Cloud root settings.** `tts-assets.config.json` `cloudRoot` is ignored; `.tools/tts-cloud/config.js` `CLOUD_ROOT` is used.
11. **Docs drift.** `.dev/custom-ui-assets/README.md` names VS Code tasks ("Custom UI Assets: Build Manifest from Image Files", merge, prune) that are not in `.vscode/tasks.json`. `.tools/Cloud-Asset-Sync-Plan.md` lists 5 of the 8 sync jobs (missing `scatterOverlay`, `memoriamBlindfolds`, `csheetPage6Assets`).
12. **Orphaned data.** `.dev/Skyboxes/Skybox URL Map.csv` (old Memoriam skybox URLs) is not referenced anywhere. `.dev/Performance Audits/Figurines *.txt` are old audit dumps of figurine URLs.
13. **PC art has two sources.** PC roll-banner rows in the save point at GitHub (`npc-art:generate`), while the seated PC figurines (`SEAT_FIGURE_*`) carry their own Steam URLs authored in the save. Named NPCs do not have this problem: their banner row uses the exact figurine URL.
14. **Dice art copied into code.** `DIE_ART` in `core/st_dice.ttslua` repeats the Standard and Hunger face-sheet URLs of the player dice objects in the save. The Rouse and Oblivion-Rouse entries match no scripted die object, so they are either different art or an outdated copy.
15. **Blood Potency images stored twice.** The decal URLs are pasted into `lib/blood_potency_constants.ttslua`, and `merge-bp-decals-into-csheets` also copies them into Page 1/2 object Custom UI assets, which no code appears to read.
16. **Dead dashboard assets.** `assets/scenes/controlBoard_*.webp`, `tokenFrame*.webp`, and the copied toast icons in `public/client/icons` have no references.

## Questions to settle before harmonizing

These are the decisions the survey surfaced; it does not answer them.

- **One host or two?** GitHub raw gives predictable URLs, content-hash cache-busting, and lets the dashboard and TTS share one file, but needs a push and makes the art public. Steam Cloud keeps art out of the public repo but its URLs can only be learned after upload.
- **Where does the name → URL list live?** Today it is split between the save (most HUD art), committed Lua catalogs, Google Sheets, and JSON files. A single committed manifest that both the save-writer and the dashboard read would remove the copy-and-lag problems in items 1, 2 and 9.
- **Should the dashboard ever hold its own copies of TTS art,** or always load the same URL TTS uses?
